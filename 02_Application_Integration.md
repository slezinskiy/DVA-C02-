# Application Integration — довідник DVA-C02

Тематичний довідник із визначеннями термінів, практичними сценаріями та
типовими екзаменаційними пастками.

## AWS AppSync

**Призначення:** Керований GraphQL API, що об’єднує джерела даних і
підтримує realtime subscriptions.

### Ключові терміни

| Термін                 | Визначення українською                                                                                                     |
|------------------------|----------------------------------------------------------------------------------------------------------------------------|
| **GraphQL**            | Мова запитів до API, де клієнт описує потрібні поля та структуру відповіді.                                                |
| **Schema**             | Контракт GraphQL API: типи, поля, аргументи та доступні операції.                                                          |
| **Query**              | GraphQL операція читання даних, яка повертає запитані клієнтом поля.                                                       |
| **Mutation**           | GraphQL операція для створення, оновлення або видалення даних.                                                             |
| **Subscription**       | GraphQL операція для отримання realtime updates від AppSync.                                                               |
| **Resolver**           | Логіка, яка отримує значення конкретного поля GraphQL із data source або обчислює його.                                    |
| **Data Source**        | Backend, до якого AppSync звертається для читання або зміни даних, наприклад DynamoDB, Lambda або HTTP endpoint.           |
| **Pipeline Resolver**  | Resolver AppSync, який послідовно запускає кілька functions, передаючи між ними context і результат.                       |
| **VTL**                | Velocity Template Language — шаблонна мова, яку AppSync використовує в resolver request/response mapping templates.        |
| **APPSYNC_JS**         | JavaScript runtime AppSync для написання resolver і pipeline functions.                                                    |
| **Authorization Mode** | Спосіб автентифікації/авторизації запитів AppSync, наприклад API key, IAM, Cognito User Pools, OIDC або Lambda authorizer. |
| **Conflict Detection** | Механізм AppSync для виявлення одночасних змін одного запису та застосування обраної стратегії розв’язання конфліктів.     |

**Типовий екзаменаційний сценарій:** Клієнту потрібен GraphQL API з
realtime оновленнями → AppSync.

**Екзаменаційна пастка:** GraphQL — API-модель, не база даних. User Pool
і IAM — різні режими авторизації.

## Amazon EventBridge

**Призначення:** Serverless event bus для маршрутизації подій за
правилами та інтеграції сервісів.

### Ключові терміни

| Термін                         | Визначення українською                                                                                                   |
|--------------------------------|--------------------------------------------------------------------------------------------------------------------------|
| **Event**                      | Структуроване повідомлення про подію, зазвичай JSON із source, detail-type, time та detail.                              |
| **Event Bus**                  | Канал EventBridge, який приймає події від джерел і маршрутизує їх за правилами до targets.                               |
| **Default/Custom/Partner Bus** | Default bus отримує AWS service events; custom bus — події застосунків; partner bus — події інтегрованих SaaS providers. |
| **Rule**                       | Конфігурація EventBridge, що зіставляє події за pattern або schedule та надсилає збіги до targets.                       |
| **Event Pattern**              | JSON-умова, яка визначає, які поля та значення події мають збігтися, щоб правило спрацювало.                             |
| **Target**                     | Сервіс або ресурс, до якого EventBridge передає подію після збігу з правилом.                                            |
| **Input Transformer**          | Налаштування EventBridge, яке витягує поля з початкової події та формує змінений payload для target.                     |
| **Archive**                    | Сховище EventBridge для збереження подій із event bus з метою подальшого replay.                                         |
| **Replay**                     | Повторне надсилання архівованих подій до event bus для відновлення або повторної обробки.                                |
| **Scheduler**                  | Amazon EventBridge Scheduler — керований сервіс одноразового або періодичного запуску AWS API actions за розкладом.      |
| **Retry**                      | Повторна доставка події до target після тимчасової помилки згідно з retry policy.                                        |
| **DLQ**                        | SQS queue для подій, які EventBridge не зміг доставити після повторних спроб.                                            |
| **Schema Registry**            | Каталог схем подій для їх пошуку, документування та генерації code bindings.                                             |

**Типовий екзаменаційний сценарій:** Потрібно маршрутизувати події за
вмістом до різних targets → EventBridge.

**Екзаменаційна пастка:** Не тотожний SQS: EventBridge маршрутизує
події, SQS буферизує повідомлення.

## Amazon SNS

**Призначення:** Pub/sub сервіс для fan-out повідомлень багатьом
підписникам.

### Ключові терміни

| Термін                   | Визначення українською                                                                                                                      |
|--------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| **Topic**                | Іменований канал SNS, у який publisher надсилає повідомлення для доставки subscribers.                                                      |
| **Publisher**            | Клієнт або AWS service, який публікує повідомлення в SNS topic.                                                                             |
| **Subscriber**           | Endpoint або сервіс, підписаний на SNS topic і здатний отримувати його повідомлення.                                                        |
| **Subscription**         | Підписка зв’язує SNS topic із endpoint і визначає протокол доставки та параметри повідомлень.                                               |
| **Fan-out**              | Архітектурний патерн, у якому одне повідомлення SNS доставляється кільком незалежним subscribers, наприклад SQS queues.                     |
| **Message Attributes**   | Додаткові структуровані метадані SNS message, які можуть використовуватися subscription filter policies.                                    |
| **Filter Policy**        | JSON-умова SNS subscription, що визначає, які повідомлення доставляти конкретному subscriber.                                               |
| **Raw Message Delivery** | Режим subscription, у якому endpoint отримує початкове message body без SNS JSON envelope.                                                  |
| **FIFO Topic**           | SNS topic із FIFO-поведінкою, message ordering і deduplication.                                                                             |
| **Deduplication**        | Механізм FIFO, який виявляє дублікати за deduplication ID або content-based hash.                                                           |
| **Delivery Policy**      | Налаштування retry для доставки повідомлень до HTTP/S endpoint.                                                                             |
| **DLQ**                  | Dead-letter queue для асинхронних Lambda invocations: місце призначення повідомлень, які не вдалося успішно обробити після повторних спроб. |

**Типовий екзаменаційний сценарій:** Одне повідомлення потрібно
доставити кільком незалежним споживачам → SNS.

**Екзаменаційна пастка:** SNS не є чергою для довготривалого споживання.
Часто поєднується з окремою SQS queue для кожного consumer.

## Amazon SQS

**Призначення:** Керована черга повідомлень для асинхронного decoupling
producer і consumer.

### Ключові терміни

| Термін                 | Визначення українською                                                                                                                                          |
|------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Standard Queue**     | Черга з високою масштабованістю та at-least-once delivery; строгий порядок не гарантується.                                                                     |
| **FIFO Queue**         | Черга з порядком у межах MessageGroupId та дедуплікацією повідомлень.                                                                                           |
| **Visibility Timeout** | Період після ReceiveMessage, протягом якого отримане повідомлення приховане від інших consumers. Якщо його не видалити, воно знову стане доступним.             |
| **Long Polling**       | Режим ReceiveMessage, коли SQS чекає до заданого часу на повідомлення, зменшуючи порожні відповіді та витрати.                                                  |
| **Short Polling**      | Режим ReceiveMessage, який повертає відповідь одразу, перевіряючи лише частину серверів SQS; може повертати порожній результат навіть за наявності повідомлень. |
| **Message Retention**  | Максимальний період, протягом якого SQS зберігає повідомлення до автоматичного видалення.                                                                       |
| **DLQ**                | Dead-letter queue для асинхронних Lambda invocations: місце призначення повідомлень, які не вдалося успішно обробити після повторних спроб.                     |
| **Redrive Policy**     | Налаштування source queue, яке визначає DLQ та максимальну кількість отримань до переміщення повідомлення.                                                      |
| **maxReceiveCount**    | Параметр redrive policy, який задає максимальну кількість отримань повідомлення перед переміщенням у DLQ.                                                       |
| **Message Group ID**   | Ідентифікатор групи FIFO-повідомлень. Порядок гарантується в межах однієї групи; різні групи можуть оброблятися паралельно.                                     |
| **Deduplication ID**   | Ідентифікатор для виявлення дублікатів FIFO-повідомлень у межах deduplication interval.                                                                         |
| **Delay Queue**        | Черга або message-level delay, що приховує повідомлення від consumer на заданий час після надсилання.                                                           |
| **At-least-once**      | Модель доставки, за якої повідомлення доставляється щонайменше один раз, але дублікати можливі; consumer має бути idempotent.                                   |

**Типовий екзаменаційний сценарій:** Потрібно буферизувати роботу,
згладжувати піки та відокремити producer від consumer → SQS.

**Екзаменаційна пастка:** Отримання не видаляє повідомлення. Після
успішної обробки потрібен DeleteMessage. Доставка може бути повторною —
потрібна idempotency.

## AWS Step Functions

**Призначення:** Керована оркестрація багатокрокових workflow між Lambda
та іншими сервісами.

### Ключові терміни

| Термін              | Визначення українською                                                                                                                                   |
|---------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **State Machine**   | Опис workflow у Step Functions як набору станів і переходів між ними.                                                                                    |
| **State**           | Окремий крок state machine, який виконує дію, перевіряє умову, очікує або завершує workflow.                                                             |
| **Task**            | Стан, який виконує роботу через AWS service integration, Lambda або інший task resource.                                                                 |
| **Choice**          | Стан Step Functions для умовного розгалуження на основі значень у state input.                                                                           |
| **Pass**            | Стан, який передає input до output або формує статичні дані без зовнішнього виклику.                                                                     |
| **Wait**            | Стан, який призупиняє workflow на заданий інтервал або до timestamp.                                                                                     |
| **Parallel**        | Стан, який запускає кілька гілок workflow паралельно та очікує їх завершення.                                                                            |
| **Map**             | Стан, який повторює набір кроків для елементів масиву вхідних даних.                                                                                     |
| **Distributed Map** | Режим Map для масштабної паралельної обробки великої кількості items через child workflow executions.                                                    |
| **Succeed**         | Термінальний стан успішного завершення workflow.                                                                                                         |
| **Fail**            | Термінальний стан, який завершує workflow із помилкою.                                                                                                   |
| **ASL**             | Amazon States Language — JSON-формат, яким описують стани, переходи, retries і обробку помилок Step Functions.                                           |
| **Standard**        | Тип Step Functions workflow для довготривалих процесів із тривалою історією виконання та exactly-once workflow execution semantics за правилами сервісу. |
| **Express**         | Тип Step Functions workflow для високочастотних коротких процесів; має іншу модель історії, тривалості та ціноутворення.                                 |
| **Retry**           | Налаштування Step Functions, яке повторює стан після визначених помилок із параметрами інтервалу, backoff і максимальної кількості спроб.                |
| **Catch**           | Налаштування Step Functions для перехоплення помилки та переходу до альтернативного стану.                                                               |
| **Execution**       | Один запуск state machine із конкретним input, execution ARN, status та history.                                                                         |
| **Task Token**      | Токен callback pattern, який зовнішня система повертає через SendTaskSuccess/SendTaskFailure для продовження workflow.                                   |

**Типовий екзаменаційний сценарій:** Потрібно координувати кроки,
retries, branching, wait та error handling → Step Functions.

**Екзаменаційна пастка:** Lambda виконує код; Step Functions координує
workflow. Standard і Express мають різні характеристики виконання та
історії.
