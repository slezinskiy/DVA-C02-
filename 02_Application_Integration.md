# Application Integration --- довідник DVA-C02

Пояснення орієнтовані на задачі розробника: призначення сервісу, ключова
термінологія, типовий сценарій та екзаменаційна пастка. \## AWS AppSync
**Призначення:** Керований GraphQL API, що об'єднує джерела даних і
підтримує realtime subscriptions. \### Ключові терміни \| Термін \|
Визначення \| \|---\|---\| \| **GraphQL** \| Мова запитів до API, де
клієнт описує потрібну структуру відповіді. \| \| **Schema** \| Контракт
GraphQL API з типами, полями, аргументами та операціями. \| \| **Query**
\| Операція читання даних у GraphQL. \| \| **Mutation** \| Операція
зміни даних у GraphQL. \| \| **Subscription** \| Зв'язок між SNS topic і
subscriber endpoint. \| \| **Resolver** \| Компонент, який пов'язує поле
API з логікою або джерелом даних. \| \| **Data Source** \|
Backend-ресурс, з якого API читає або в який записує дані. \| \|
**Pipeline Resolver** \| Resolver, який виконує кілька функцій
послідовно. \| \| **VTL** \| Ключовий компонент або поняття AWS AppSync;
визначає відповідну частину конфігурації, виконання чи інтеграції
сервісу. \| \| **APPSYNC_JS** \| Ключовий компонент або поняття AWS
AppSync; визначає відповідну частину конфігурації, виконання чи
інтеграції сервісу. \| \| **Authorization Mode** \| Ключовий компонент
або поняття AWS AppSync; визначає відповідну частину конфігурації,
виконання чи інтеграції сервісу. \| \| **Conflict Detection** \|
Ключовий компонент або поняття AWS AppSync; визначає відповідну частину
конфігурації, виконання чи інтеграції сервісу. \|

**Типовий екзаменаційний сценарій:** Клієнту потрібен GraphQL API з
realtime оновленнями → AppSync.

**Екзаменаційна пастка:** GraphQL --- API-модель, не база даних. User
Pool і IAM --- різні режими авторизації.

  \## Amazon SNS
  **Призначення:** Pub/sub
  сервіс для fan-out
  повідомлень багатьом
  підписникам. \### Ключові
  терміни \| Термін \|
  Визначення \| \|---\|---\|
  \| **Topic** \| Логічний
  канал, у який publisher
  надсилає повідомлення. \|
  \| **Publisher** \|
  Відправник, який публікує
  повідомлення в SNS topic.
  \| \| **Subscriber** \|
  Endpoint, який отримує
  повідомлення з SNS topic.
  \| \| **Subscription** \|
  Зв'язок між SNS topic і
  subscriber endpoint. \| \|

  кільком незалежним
  підписникам. \| \|
  **Message Attributes** \|

  для фільтрації. \| \|
  **Filter Policy** \|
  Умова, за якою SNS
  вирішує, чи доставляти
  повідомлення певній
  subscription. \| \| **Raw
  Message Delivery** \|

  поняття Amazon SNS;
  визначає відповідну
  частину конфігурації,

  сервісу. \| \| **Delivery
  Policy** \| Ключовий
  компонент або поняття
  Amazon SNS; визначає
  відповідну частину
  конфігурації, виконання чи
  інтеграції сервісу. \| \|
  **DLQ** \| Ключовий

  конфігурації, виконання чи

  **Типовий екзаменаційний

  окремою SQS queue для
  кожного consumer.

## Amazon SQS

**Призначення:** Керована черга повідомлень для асинхронного decoupling
producer і consumer. \### Ключові терміни \| Термін \| Визначення \|
\|---\|---\| \| **Standard Queue** \| Ключовий компонент або поняття
Amazon SQS; визначає відповідну частину конфігурації, виконання чи
інтеграції сервісу. \| \| **FIFO Queue** \| Ключовий компонент або
поняття Amazon SQS; визначає відповідну частину конфігурації, виконання
чи інтеграції сервісу. \| \| **Visibility Timeout** \| Період, коли
отримане SQS повідомлення приховане від інших consumer. \| \| **Long
Polling** \| Очікування повідомлення до заданого часу, що зменшує
порожні receive calls. \| \| **Short Polling** \| Негайне опитування
черги без тривалого очікування. \| \| **Message Retention** \|
Максимальний час зберігання повідомлення в черзі. \| \| **DLQ** \|
Ключовий компонент або поняття Amazon SQS; визначає відповідну частину
конфігурації, виконання чи інтеграції сервісу. \| \| **Redrive Policy**
\| Правило, яке визначає умови переміщення повідомлення до DLQ. \| \|
**maxReceiveCount** \| Максимальна кількість отримань повідомлення до
переміщення в DLQ. \| \| **Message Group ID** \| Ідентифікатор групи
FIFO, у межах якої зберігається порядок. \| \| **Deduplication ID** \|
Ідентифікатор, який допомагає виявляти дублікати FIFO-повідомлень. \| \|
**Delay Queue** \| Ключовий компонент або поняття Amazon SQS; визначає
відповідну частину конфігурації, виконання чи інтеграції сервісу. \| \|
**At-least-once** \| Модель доставки, за якої повідомлення може бути
доставлене повторно. \|

**Типовий екзаменаційний сценарій:** Потрібно буферизувати роботу,
згладжувати піки та відокремити producer від consumer → SQS.

**Екзаменаційна пастка:** Отримання не видаляє повідомлення. Після
успішної обробки потрібен DeleteMessage. Доставка може бути повторною
--- потрібна idempotency.
