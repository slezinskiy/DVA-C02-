# Application Integration — довідник DVA-C02

Ключові поняття, сценарії та типові екзаменаційні пастки для сервісів
цієї категорії.

## AWS AppSync

**Призначення:** Керований GraphQL API, що об’єднує джерела даних і
підтримує realtime subscriptions.

### Ключові терміни

| Термін                 | Визначення                                                                                                             |
|------------------------|------------------------------------------------------------------------------------------------------------------------|
| **GraphQL**            | Мова запитів до API, де клієнт описує потрібну структуру відповіді.                                                    |
| **Schema**             | Контракт GraphQL API з типами, полями, аргументами та операціями.                                                      |
| **Query**              | Операція читання даних у GraphQL.                                                                                      |
| **Mutation**           | Операція зміни даних у GraphQL.                                                                                        |
| **Subscription**       | Зв’язок між SNS topic і subscriber endpoint.                                                                           |
| **Resolver**           | Компонент, який пов’язує поле API з логікою або джерелом даних.                                                        |
| **Data Source**        | Backend-ресурс, з якого API читає або в який записує дані.                                                             |
| **Pipeline Resolver**  | Resolver, який виконує кілька функцій послідовно.                                                                      |
| **VTL**                | У контексті AWS AppSync це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **APPSYNC_JS**         | У контексті AWS AppSync це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Authorization Mode** | У контексті AWS AppSync це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Conflict Detection** | У контексті AWS AppSync це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |

**Типовий екзаменаційний сценарій:** Клієнту потрібен GraphQL API з
realtime оновленнями → AppSync.

**Екзаменаційна пастка:** GraphQL — API-модель, не база даних. User Pool
і IAM — різні режими авторизації.

## Amazon EventBridge

**Призначення:** Serverless event bus для маршрутизації подій за
правилами та інтеграції сервісів.

### Ключові терміни

| Термін                         | Визначення                                                                                                                    |
|--------------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| **Event**                      | Повідомлення про факт або зміну, що сталася.                                                                                  |
| **Event Bus**                  | Канал, який приймає події та маршрутизує їх до targets.                                                                       |
| **Default/Custom/Partner Bus** | У контексті Amazon EventBridge це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Rule**                       | Умова зіставлення події та конфігурація її подальшої доставки.                                                                |
| **Event Pattern**              | Опис структури/значень полів події, які мають збігтися з правилом.                                                            |
| **Target**                     | Сервіс або ресурс, якому передається подія.                                                                                   |
| **Input Transformer**          | Правило перетворення payload перед передаванням target.                                                                       |
| **Archive**                    | Збереження подій EventBridge для подальшого replay.                                                                           |
| **Replay**                     | Повторне відтворення раніше збережених подій.                                                                                 |
| **Scheduler**                  | Керований запуск дії одноразово або за розкладом.                                                                             |
| **Retry**                      | Правило повторного запуску стану після помилки.                                                                               |
| **DLQ**                        | У контексті Amazon EventBridge це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Schema Registry**            | У контексті Amazon EventBridge це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |

**Типовий екзаменаційний сценарій:** Потрібно маршрутизувати події за
вмістом до різних targets → EventBridge.

**Екзаменаційна пастка:** Не тотожний SQS: EventBridge маршрутизує
події, SQS буферизує повідомлення.

## Amazon SNS

**Призначення:** Pub/sub сервіс для fan-out повідомлень багатьом
підписникам.

### Ключові терміни

| Термін                   | Визначення                                                                                                            |
|--------------------------|-----------------------------------------------------------------------------------------------------------------------|
| **Topic**                | Логічний канал, у який publisher надсилає повідомлення.                                                               |
| **Publisher**            | Відправник, який публікує повідомлення в SNS topic.                                                                   |
| **Subscriber**           | Endpoint, який отримує повідомлення з SNS topic.                                                                      |
| **Subscription**         | Зв’язок між SNS topic і subscriber endpoint.                                                                          |
| **Fan-out**              | Передача одного повідомлення кільком незалежним підписникам.                                                          |
| **Message Attributes**   | Метадані повідомлення, які можуть використовуватися для фільтрації.                                                   |
| **Filter Policy**        | Умова, за якою SNS вирішує, чи доставляти повідомлення певній subscription.                                           |
| **Raw Message Delivery** | У контексті Amazon SNS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **FIFO Topic**           | У контексті Amazon SNS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Deduplication**        | У контексті Amazon SNS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Delivery Policy**      | У контексті Amazon SNS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **DLQ**                  | У контексті Amazon SNS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |

**Типовий екзаменаційний сценарій:** Одне повідомлення потрібно
доставити кільком незалежним споживачам → SNS.

**Екзаменаційна пастка:** SNS не є чергою для довготривалого споживання.
Часто поєднується з окремою SQS queue для кожного consumer.

## Amazon SQS

**Призначення:** Керована черга повідомлень для асинхронного decoupling
producer і consumer.

### Ключові терміни

| Термін                 | Визначення                                                                                                            |
|------------------------|-----------------------------------------------------------------------------------------------------------------------|
| **Standard Queue**     | У контексті Amazon SQS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **FIFO Queue**         | У контексті Amazon SQS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Visibility Timeout** | Період, коли отримане SQS повідомлення приховане від інших consumer.                                                  |
| **Long Polling**       | Очікування повідомлення до заданого часу, що зменшує порожні receive calls.                                           |
| **Short Polling**      | Негайне опитування черги без тривалого очікування.                                                                    |
| **Message Retention**  | Максимальний час зберігання повідомлення в черзі.                                                                     |
| **DLQ**                | У контексті Amazon SQS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Redrive Policy**     | Правило, яке визначає умови переміщення повідомлення до DLQ.                                                          |
| **maxReceiveCount**    | Максимальна кількість отримань повідомлення до переміщення в DLQ.                                                     |
| **Message Group ID**   | Ідентифікатор групи FIFO, у межах якої зберігається порядок.                                                          |
| **Deduplication ID**   | Ідентифікатор, який допомагає виявляти дублікати FIFO-повідомлень.                                                    |
| **Delay Queue**        | У контексті Amazon SQS це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **At-least-once**      | Модель доставки, за якої повідомлення може бути доставлене повторно.                                                  |

**Типовий екзаменаційний сценарій:** Потрібно буферизувати роботу,
згладжувати піки та відокремити producer від consumer → SQS.

**Екзаменаційна пастка:** Отримання не видаляє повідомлення. Після
успішної обробки потрібен DeleteMessage. Доставка може бути повторною —
потрібна idempotency.

## AWS Step Functions

**Призначення:** Керована оркестрація багатокрокових workflow між Lambda
та іншими сервісами.

### Ключові терміни

| Термін              | Визначення                                                                                                                    |
|---------------------|-------------------------------------------------------------------------------------------------------------------------------|
| **State Machine**   | Опис workflow як станів і переходів між ними.                                                                                 |
| **State**           | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Task**            | Стан Step Functions, який виконує роботу через сервісну інтеграцію або код.                                                   |
| **Choice**          | Стан умовного розгалуження workflow.                                                                                          |
| **Pass**            | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Wait**            | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Parallel**        | Стан, що запускає кілька гілок workflow паралельно.                                                                           |
| **Map**             | Стан, що повторює кроки для елементів набору даних.                                                                           |
| **Distributed Map** | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Succeed**         | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Fail**            | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **ASL**             | Amazon States Language — JSON-мова опису Step Functions state machine.                                                        |
| **Standard**        | Тип workflow для довших виконань із детальнішою історією та іншими гарантіями виконання.                                      |
| **Express**         | Тип workflow для високочастотних коротких виконань із відмінною моделлю історії/вартості.                                     |
| **Retry**           | Правило повторного запуску стану після помилки.                                                                               |
| **Catch**           | Обробник помилки, який переводить workflow до альтернативного стану.                                                          |
| **Execution**       | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |
| **Task Token**      | У контексті AWS Step Functions це поняття описує відповідний елемент сервісу, його налаштування або поведінку під час роботи. |

**Типовий екзаменаційний сценарій:** Потрібно координувати кроки,
retries, branching, wait та error handling → Step Functions.

**Екзаменаційна пастка:** Lambda виконує код; Step Functions координує
workflow. Standard і Express мають різні характеристики виконання та
історії.
