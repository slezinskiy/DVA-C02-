# Storage — довідник DVA-C02

Тематичний довідник із визначеннями термінів, практичними сценаріями та
типовими екзаменаційними пастками.

## Amazon EBS

**Призначення:** Блокове сховище, яке підключається до EC2 як
віртуальний диск.

### Ключові терміни

| Термін                    | Визначення українською                                                                                                                                                                   |
|---------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Volume**                | Віртуальний блоковий диск EBS, який можна підключити до EC2 у тій самій Availability Zone.                                                                                               |
| **Snapshot**              | Інкрементальна point-in-time резервна копія EBS volume. Після першого snapshot наступні зберігають лише змінені блоки; із snapshot можна створити volume в іншій AZ або Region.          |
| **Volume Type**           | Клас EBS volume, який визначає характеристики продуктивності та ціну. Основні типи: gp3/gp2 (general purpose SSD), io2/io1 (provisioned IOPS SSD), st1 (throughput HDD), sc1 (cold HDD). |
| **IOPS**                  | Input/Output Operations Per Second — кількість операцій читання/запису за секунду. Важливо для workload із великою кількістю дрібних випадкових операцій.                                |
| **Throughput**            | Обсяг даних, який передається за одиницю часу, зазвичай MiB/s. Особливо важливий для послідовного читання/запису.                                                                        |
| **Latency**               | Затримка між запитом на I/O та його завершенням. Низька latency важлива для транзакційних і чутливих до часу застосунків.                                                                |
| **Provisioned IOPS**      | Задана користувачем продуктивність IOPS для підтримуваних типів EBS, насамперед io1/io2; допомагає передбачити продуктивність інтенсивного I/O.                                          |
| **Encryption**            | Шифрування EBS volume і snapshots за допомогою AWS KMS. Шифрування захищає дані at rest та підтримується прозоро для EC2.                                                                |
| **Multi-Attach**          | Функція io1/io2, яка дозволяє підключити один EBS volume до кількох сумісних EC2 instances в одній AZ. Потрібна кластерна файлова система або механізм координації запису.               |
| **Elastic Volumes**       | Можливість змінити розмір, тип або продуктивність підтримуваного EBS volume без від’єднання від EC2, з урахуванням обмежень модифікації.                                                 |
| **Root/Data Volume**      | Root volume містить операційну систему EC2; data volume зберігає дані застосунку окремо від системного диска.                                                                            |
| **AZ Scope**              | EBS volume прив’язаний до однієї Availability Zone. Для використання в іншій AZ створюють snapshot і відновлюють із нього новий volume у цільовій AZ.                                    |
| **Fast Snapshot Restore** | Функція, яка забезпечує повну продуктивність EBS volume, створеного зі snapshot, без поступової ініціалізації блоків у вибраних AZ.                                                      |

**Типовий екзаменаційний сценарій:** Потрібен постійний block device для
EC2 → EBS.

**Екзаменаційна пастка:** EBS volume прив’язаний до Availability Zone;
для перенесення використовують snapshot і створюють volume в іншій AZ.

## Amazon EFS

**Призначення:** Еластична спільна мережева файлова система для Linux
workloads.

### Ключові терміни

| Термін                     | Визначення українською                                                                                                    |
|----------------------------|---------------------------------------------------------------------------------------------------------------------------|
| **File System**            | Спільна мережева файлова система EFS, доступна Linux clients через NFS.                                                   |
| **Mount Target**           | Мережевий endpoint EFS у subnet/AZ, через який клієнти монтують файлову систему.                                          |
| **NFS**                    | Network File System — мережевий протокол доступу до файлів; EFS підтримує NFSv4.1.                                        |
| **Access Point**           | EFS endpoint із заданим root directory та POSIX identity для ізольованого доступу застосунку.                             |
| **POSIX Permissions**      | Права Linux filesystem: власник, група та read/write/execute для owner/group/others.                                      |
| **UID/GID**                | Числові ідентифікатори Linux user і group, які визначають власність файлів та права доступу.                              |
| **Performance Mode**       | Профіль EFS для характеристик latency та масштабування I/O, наприклад General Purpose або Max I/O (де підтримується).     |
| **Throughput Mode**        | Спосіб надання throughput EFS: Bursting, Provisioned або Elastic.                                                         |
| **Bursting**               | Throughput mode, де доступна пропускна здатність залежить від обсягу збережених даних і burst credits.                    |
| **Elastic Throughput**     | Режим, який автоматично підлаштовує throughput під фактичний workload.                                                    |
| **Provisioned Throughput** | Режим, де користувач задає throughput незалежно від обсягу даних.                                                         |
| **Lifecycle Management**   | Автоматичне переміщення файлів у дешевші EFS storage classes після періоду без доступу.                                   |
| **IA**                     | Infrequent Access — дешевший клас EFS для файлів, до яких звертаються нечасто.                                            |
| **One Zone**               | EFS storage class, що зберігає дані в одній AZ; дешевший, але з нижчою доступністю при втраті AZ.                         |
| **Encryption**             | Шифрування EBS volume і snapshots за допомогою AWS KMS. Шифрування захищає дані at rest та підтримується прозоро для EC2. |

**Типовий екзаменаційний сценарій:** Кілька Linux instances потребують
спільної файлової системи → EFS.

**Екзаменаційна пастка:** EFS — file storage через NFS; EBS — block
storage для instance; S3 — object storage.

## Amazon S3

**Призначення:** Об’єктне сховище для файлів, backup, data lakes, static
content та інтеграцій.

### Ключові терміни

| Термін                    | Визначення українською                                                                                                                 |
|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| **Bucket**                | S3 контейнер для зберігання об’єктів. Bucket має глобально унікальне ім’я в межах partition AWS і налаштування доступу/регіону.        |
| **Object**                | Одиниця зберігання S3, що складається з даних, key та metadata.                                                                        |
| **Key**                   | Унікальне ім’я об’єкта в межах S3 bucket. Prefix-и імітують ієрархію папок, але S3 має плоский простір ключів.                         |
| **Prefix**                | Початкова частина S3 object key для логічного групування та пошуку об’єктів; це не справжня директорія.                                |
| **Bucket Policy**         | Resource-based JSON policy, яка визначає доступ до bucket та його objects.                                                             |
| **ACL**                   | Access Control List — старіший механізм доступу до bucket/object; зазвичай рекомендовано використовувати policies та вимкнути ACL.     |
| **Block Public Access**   | Набір налаштувань S3, що блокує публічний доступ на рівні account або bucket незалежно від окремих ACL/policies у визначених випадках. |
| **Versioning**            | Функція S3, яка зберігає кілька версій об’єкта з однаковим key; дозволяє відновлювати попередні версії.                                |
| **Delete Marker**         | Спеціальна версія у versioned bucket, яка приховує об’єкт від звичайного GET, але не видаляє попередні версії.                         |
| **Lifecycle**             | Набір правил для автоматичного переходу об’єктів між storage classes або expiration.                                                   |
| **Storage Class**         | Клас зберігання S3, який визначає вартість, доступність і retrieval model: Standard, Intelligent-Tiering, IA та Glacier classes.       |
| **Glacier**               | Сімейство архівних S3 storage classes із дешевшим зберіганням і різними строками/вартістю відновлення.                                 |
| **Replication**           | Асинхронне автоматичне копіювання об’єктів між buckets за replication rules.                                                           |
| **CRR/SRR**               | Cross-Region Replication копіює об’єкти в інший Region; Same-Region Replication — в інший bucket того самого Region.                   |
| **Multipart Upload**      | Механізм S3 для завантаження великого об’єкта частинами; невдалі частини можна повторити окремо.                                       |
| **Presigned URL**         | URL із тимчасовим підписом, який надає обмежений у часі доступ до конкретного S3 object без розкриття AWS credentials.                 |
| **Event Notification**    | Подія S3 про object operation, яку можна доставити в SNS, SQS, Lambda або EventBridge.                                                 |
| **Object Lock**           | S3 механізм WORM (Write Once Read Many), що захищає об’єкти від видалення/перезапису протягом retention period або legal hold.         |
| **SSE-S3**                | Server-side encryption, де S3 керує ключами шифрування об’єкта.                                                                        |
| **SSE-KMS**               | Server-side encryption, де S3 використовує AWS KMS key для шифрування об’єктів.                                                        |
| **SSE-C**                 | Server-side encryption із customer-provided encryption key, який клієнт передає під час запитів.                                       |
| **Transfer Acceleration** | Функція S3, що використовує edge network для прискорення завантажень до віддаленого bucket.                                            |
| **Access Point**          | Іменований S3 endpoint із власною policy та network controls для доступу до bucket.                                                    |
| **Inventory**             | Періодичний звіт про об’єкти bucket та їх metadata для аудиту й аналітики.                                                             |
| **Storage Lens**          | Аналітика S3 для огляду використання storage, активності та оптимізації.                                                               |
| **ETag**                  | Ідентифікатор представлення об’єкта, який повертає S3; не завжди є MD5 checksum, особливо для multipart uploads.                       |

**Типовий екзаменаційний сценарій:** Потрібне масштабоване object
storage або статичний контент → S3.

**Екзаменаційна пастка:** S3 має strong read-after-write consistency для
PUT/DELETE. ETag не завжди дорівнює MD5; приватний CloudFront origin
захищайте OAC.
