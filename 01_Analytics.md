# Analytics — довідник DVA-C02

Тематичний довідник із визначеннями термінів, практичними сценаріями та
типовими екзаменаційними пастками.

## Amazon Athena

**Призначення:** Serverless SQL-запити до даних, що зазвичай
зберігаються в Amazon S3.

### Ключові терміни

| Термін                | Визначення українською                                                                                                                                 |
|-----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Workgroup**         | Логічний контейнер Athena для ізоляції запитів, налаштувань, контролю витрат, доступу та розташування результатів.                                     |
| **Glue Data Catalog** | Центральний каталог метаданих AWS Glue з описами баз даних, таблиць, схем і розташуванням даних, які можуть використовувати Athena.                    |
| **External Table**    | Таблиця Athena, що містить метадані та схему файлів у зовнішньому сховищі (часто S3), але не копіює самі дані.                                         |
| **Partitioning**      | Поділ набору даних на частини за значеннями колонок, наприклад дата/регіон. Дозволяє Athena читати лише потрібні partitions і зменшувати scanned data. |
| **Parquet/ORC**       | Колонкові формати файлів, оптимізовані для аналітичних запитів. Зазвичай зменшують обсяг читання порівняно з текстовими форматами.                     |
| **Query Execution**   | Окремий запуск SQL-запиту Athena з унікальним QueryExecutionId, статусом, статистикою та результатом.                                                  |
| **Result Location**   | S3 bucket/prefix, куди Athena записує результати SQL-запиту та метадані виконання.                                                                     |
| **CTAS**              | CREATE TABLE AS SELECT — SQL-операція Athena, яка створює таблицю на основі результату SELECT, часто для перетворення даних у Parquet/ORC.             |
| **Federated Query**   | Можливість Athena запитувати дані в зовнішніх джерелах через data source connectors, а не лише файли в S3.                                             |

**Типовий екзаменаційний сценарій:** SQL-аналітика файлів у S3 без
розгортання БД → Athena.

**Екзаменаційна пастка:** Оплата залежить від обсягу просканованих
даних; фільтрація й partitioning зменшують сканування. Glue Catalog
зберігає метадані, не самі файли.

## Amazon Kinesis

**Призначення:** Сімейство сервісів для приймання, потокової обробки та
доставки подій.

### Ключові терміни

| Термін               | Визначення українською                                                                                                                                                    |
|----------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Data Streams**     | Amazon Kinesis Data Streams — керований потік записів, які producers публікують, а consumers читають і обробляють.                                                        |
| **Data Firehose**    | Amazon Data Firehose — керована доставка потокових даних до призначень, наприклад S3, Redshift, OpenSearch або HTTP endpoint, із буферизацією та опційною трансформацією. |
| **Producer**         | Застосунок або сервіс, який створює та надсилає записи до потоку або повідомлення до черги/topic.                                                                         |
| **Consumer**         | Застосунок або сервіс, який отримує записи з потоку або повідомлення з черги/topic і виконує їх обробку.                                                                  |
| **Shard**            | Одиниця ємності та паралелізму Kinesis Data Streams. Кожен shard має діапазон partition keys і власний порядок sequence numbers.                                          |
| **Partition Key**    | Значення, за яким Kinesis Data Streams обчислює hash і спрямовує запис до shard; однаковий key спрямовує записи до того самого shard.                                     |
| **Sequence Number**  | Ідентифікатор запису в межах shard Kinesis; допомагає визначити позицію запису та порядок читання.                                                                        |
| **Retention**        | Період, протягом якого записи залишаються доступними в Kinesis Data Streams для повторного читання.                                                                       |
| **Enhanced Fan-Out** | Режим Kinesis Data Streams, у якому registered consumer отримує виділену пропускну здатність читання через HTTP/2 SubscribeToShard.                                       |
| **KCL**              | Kinesis Client Library — бібліотека, що координує читання shard, балансування між workers і збереження checkpoint для consumer application.                               |
| **Checkpoint**       | Збережена позиція читання в shard, з якої consumer може продовжити обробку після перезапуску.                                                                             |
| **Resharding**       | Операція збільшення або зменшення кількості shard Kinesis Data Streams для зміни загальної пропускної здатності.                                                          |
| **Buffering**        | Накопичення даних до досягнення заданого розміру або часу перед доставкою, зокрема в Firehose.                                                                            |

**Типовий екзаменаційний сценарій:** Потрібен контроль consumer та
повторне читання потоку → Data Streams; потрібна керована доставка в S3
→ Firehose.

**Екзаменаційна пастка:** Kinesis Streams — журнал потоку для consumer;
SQS — черга повідомлень. Не плутати Data Streams із Data Firehose.

## Amazon OpenSearch Service

**Призначення:** Керований пошуковий та аналітичний рушій для
повнотекстового пошуку, логів і observability.

### Ключові терміни

| Термін             | Визначення українською                                                                                                           |
|--------------------|----------------------------------------------------------------------------------------------------------------------------------|
| **Domain**         | Керований deployment OpenSearch Service, що містить кластер, мережеві та security налаштування.                                  |
| **Cluster**        | Набір OpenSearch nodes, які разом зберігають shards та обробляють запити.                                                        |
| **Node**           | Окремий вузол OpenSearch cluster із роллю data, ingest або cluster manager.                                                      |
| **Index**          | Логічна колекція документів OpenSearch, оптимізована для пошуку та аналітики.                                                    |
| **Document**       | JSON-запис, який індексується та зберігається в OpenSearch.                                                                      |
| **Mapping**        | Опис типів полів і правил індексації документів у OpenSearch.                                                                    |
| **Inverted Index** | Структура пошукового індексу, що зіставляє терміни з документами, у яких вони зустрічаються.                                     |
| **Analyzer**       | Компонент OpenSearch, який розбиває текст на tokens і може нормалізувати їх перед індексацією або пошуком.                       |
| **Shard**          | Одиниця ємності та паралелізму Kinesis Data Streams. Кожен shard має діапазон partition keys і власний порядок sequence numbers. |
| **Replica**        | Копія shard OpenSearch, що підвищує доступність і може розподіляти навантаження читання.                                         |
| **Query DSL**      | JSON-мова OpenSearch для побудови пошукових запитів, фільтрів і умов.                                                            |
| **Aggregation**    | Операція OpenSearch для групування та обчислення статистики над набором документів.                                              |
| **Snapshot**       | Резервна копія OpenSearch indexes та cluster state, яка зберігається у snapshot repository, зазвичай S3.                         |
| **Ingestion**      | Надходження, перетворення та індексація даних у OpenSearch через clients або ingestion pipelines.                                |

**Типовий екзаменаційний сценарій:** Потрібен повнотекстовий пошук або
пошук по логах → OpenSearch.

**Екзаменаційна пастка:** Не є транзакційною реляційною БД чи заміною
DynamoDB для key-value доступу.
